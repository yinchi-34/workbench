# 一、功能层

需求本身的问题，与技术栈无关。

## 边界与状态

- [ ] 空值、超长、超量、重复等边界输入的处理是否符合 spec
- [ ] 状态转换是否完整：每个中间状态都有确定的后续状态，不会长期停留（例如 pending、streaming）
- [ ] 部分失败时的结果是否一致：要么全部成功，要么全部回滚，或有明确的补偿方式

## 权限与输入

- [ ] 资源归属校验：是否可能访问他人的数据（例如跨会话引用）
- [ ] 是否限制输入的长度与数量；是否校验前端传入的数据，避免直接采信前端计算的值（例如选区位置）
- [ ] 错误信息是否泄露内部实现（SQL、堆栈、文件路径）

## 幂等

- [ ] 重复提交或重试是否会产生重复数据（例如连续两次点击发送）
- [ ] 需要幂等的接口是否有幂等键或唯一约束

## 交互边界

- [ ] 操作入口是否只出现在允许的范围内（例如是否允许引用用户本人的消息）
- [ ] 取消、中断、返回等非正常路径的处理是否符合 spec
