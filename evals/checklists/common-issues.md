# 常见问题清单（持续更新）

收尾验收第三步和专项审查用。不是每条都适用，挑和改动相关的查；查过的每条都写结论，"不适用"也写。

业务仓库复制一份到 docs/checklist.md，项目特有的坑加在后面；通用的坑回写到这里。

## 数据库

- [ ] N+1 查询：循环里有没有逐条查库
- [ ] 外键和级联删除是否真的生效（SQLite 每个连接都要执行 `PRAGMA foreign_keys = ON`）
- [ ] 事务边界是否正确：该一起写入的数据在同一个事务里，出错时返回错误而不是只打日志
- [ ] 时间是否统一用 UTC

## 并发

- [ ] 共享数据有没有加锁，加锁顺序会不会导致死锁
- [ ] goroutine 或线程能不能正确退出，有没有泄漏
- [ ] SQLite 并发写入会不会报 database is locked

## 幂等性

- [ ] 重复提交、重试会不会产生重复数据（例如连点两次发送）

## 缓存（Redis）

- [ ] Lua 脚本是否保证原子性
- [ ] 缓存雪崩、穿透、击穿有没有防护
- [ ] 缓存和数据库之间的一致性

## 接口与安全

- [ ] 资源归属校验：能不能访问到别人的数据（例如跨会话引用）
- [ ] 输入长度和数量是否有限制，前端传来的数据是否做了校验，不信任前端算的位置
- [ ] 改接口前是否查了 docs/api-index.md，"谁依赖它"都检查过

## 流式与长连接

- [ ] 客户端断开后，服务端是否及时释放资源（context 取消后 goroutine 退出）
- [ ] 超时和错误时消息状态是否正确，不会一直停在 pending / streaming

## 前端

- [ ] 跨元素选区、Markdown 渲染前后的文字位置是否对得上
- [ ] 选区落在按钮、用户自己的消息上时的处理是否符合 spec
- [ ] 移动端长按选择和边界输入

## 测试本身

- [ ] 测试是否真的断言了结果，而不只是"没报错"
- [ ] 有没有被放宽的断言、被跳过或删掉的测试
- [ ] 异常和边界情况是否覆盖
