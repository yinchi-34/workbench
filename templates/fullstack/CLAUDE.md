## 项目管理总控

开始时在主会话调用 `/role-project-manager <功能名>`，阅读该技能的公共规则和工具约定。
项目管理负责交接、状态、阻塞与验收证据，人工负责需求、方案、优先级、计划及最终验收。

### 会话分工
- 轻量：当前主会话承担项目管理及需求协调，按批准计划调用规划、执行与审查角色。
- 完整：项目管理是总控主会话；前后端负责人各在独立 worktree 的主会话调用 `/role-lead <领域> <功能名>`，负责本领域编排。
- 产品经理按 role-product-manager 起草 spec，设计分歧由其分析、项目管理汇总、人工决定。
- 子 agent 只执行有边界的工作并交回公共报告；需人工决定时返回“状态：待人工决定”，不在子 agent 中等待或自行批准。

### 顺序与版本
1. 需求设计、协作档位及方案提交人工批准。
2. 完整档位由后端提出契约、前端反馈，人工批准后，项目管理登记协调分支和文档提交 SHA。
3. 各 worktree 同步同一批准版本后，规划者拆任务、确定 AC 与证据要求，任务计划交人工审阅。
4. 执行者按任务实施，交“待审查”；审查者独立检查，附件结论为通过 / 需修改 / 无法验证。
5. 已批准的修复交执行者，之后复查；需调整设计、契约、测试或范围时提交人工决定。同一任务两轮审查未通过交人工处理。
6. 项目管理汇总 AC 证据和集成结果，进入待验收；人工批准后才登记已验收并调用 retro 复盘。

### 持久记录
- docs/project/tasks.md：由项目管理维护任务与依赖，看板是其映射。
- docs/project/decisions.md：人工决定、来源及适用版本，不允许虚构批准。
- docs/acceptance/<功能名>.md：证据、审查、集成及人工验收。
- spec 与 api-index 为业务与契约依据，报告和看板不得代替它们。

MCP/CLI 不具备会话派发或看板权限时，保留未同步项与人工转交指令，不宣称已发送或已更新。
