## 文档

## 约定

- 测试文件只有人同意才能改，包括放宽断言、跳过、删除。
- 改接口前先查 docs/api-index.md，"谁依赖它"一栏的每一项都要检查。
- API 设计和数据模型由后端负责，前端只提需求。

## 评审重点

GitHub 上的 Codex 评审只读本文件，所以评审重点在这里写一份摘要：

- 测试是否真的覆盖了 spec 的验收标准，有没有被改过。
- 资源归属校验、输入限制、事务边界。
- 流式接口在客户端断开后是否释放资源。
- 按严重程度分级给出问题，带文件和行号。
