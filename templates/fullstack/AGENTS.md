## 约定

- 测试文件须经人工同意方可修改，包括放宽断言、跳过或删除测试。
- 修改接口前须查阅 docs/api-index.md，并逐项检查"谁依赖它"一栏。
- API 设计与数据模型由后端负责，前端仅提出需求。

## 评审重点

GitHub 上的 Codex 评审仅读取本文件，因此在此列出评审重点摘要：

- 测试是否覆盖 spec 的验收标准，测试文件是否被修改。
- 资源归属校验、输入限制、事务边界。
- 流式接口在客户端断开后是否释放资源。
- 按严重程度分级列出问题，并注明文件与行号。

## 项目管理与验收

- 项目管理为总控，维护 docs/project/tasks.md 和 decisions.md；轻量档位由当前主会话承担。
- 各角色阅读 role-project-manager 技能的 references/protocol.md，以统一格式交接。
- 人工保留需求、方案、优先级、计划、契约、测试调整与最终验收的决策权；角色推进已批准工作。
- docs/acceptance/<功能名>.md 按 AC 记录提交 SHA、环境、命令或步骤、实际结果与证据位置。
- 审查通过仅代表可提交验收；人工批准后才能标记已验收。版本变化须复核受影响的证据。
