## 文档

| 文档 | 作用 |
|------|------|
| docs/specs/<功能名>.md | 功能 spec，按 requirements-design 技能编写 |
| docs/api-index.md | 接口影响索引，修改接口前须先查阅 |
| docs/plans/<功能名>-<前端/后端>.md | 规划者拆出的任务列表 |
| docs/checklist.md | 常见问题清单（复制自 workbench，项目特有的问题追加在后面） |
| docs/examples/ | 各角色输出格式的示例 |
| docs/notes/ | 问题记录：AI 的输出、发现问题的方式及修复过程 |

## 约定

- 测试文件须经人工同意方可修改，包括放宽断言、跳过或删除测试。
- 修改接口前须查阅 docs/api-index.md，并逐项检查"谁依赖它"一栏。
- API 设计与数据模型由后端负责，前端仅提出需求。

## 评审重点

GitHub 上的 Codex 评审仅读取本文件，因此在此列出评审重点摘要：

- 测试是否覆盖 spec 的验收标准，测试文件是否被修改。
- 资源归属校验、输入限制、事务边界。
- 流式接口在客户端断开后是否释放资源。
- 按严重程度分级列出问题，并注明文件与行号。
