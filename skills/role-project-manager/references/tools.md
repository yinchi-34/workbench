# MCP 与工具接入约定

MCP 提供读写能力；项目管理角色推动流程；人工决定取舍。无需为工具调用本身再增加一层决策者。

## 接入前
按当前环境实际工具清单检查能力，不假设存在固定名称的工具：

| 需要的能力 | 用途 | 缺失时 |
|------------|------|--------|
| 读取 Issue / PR / 提交 / CI | 核实实现与验证状态 | 使用已授权 CLI，或记录待获取证据 |
| 读取及更新任务看板 | 映射任务状态、登记依赖 | 以本地账本继续跟踪 |
| 读写项目文件 | 保存交接、批准和验收记录 | 输出待保存内容，注明未落盘 |
| 会话派发及查询 | 转交角色并观察结果 | 输出人工转交指令 |

优先沿用项目已有工具；仓库基底规定 CLI 可完成时不额外调用 MCP。未经配置的服务不伪造地址或成功结果。
仓库现有 mcp/servers.json 的 Context7 是文档查询能力，不提供任务管理、PR 或 CI 接入。
需要新增服务时，人工选定服务并授权后，将真实配置按该服务文档加入 mcp/servers.json；密钥只引用环境变量。

## 读写
- 查询状态后注明数据来源、查询时间和提交版本。连接失败、权限不足分别报告，未知不能当作完成。
- 看板写入等外部变更必须在人工授权的范围内；无授权时产出待同步内容。批准某项需求不自动授权发布、合并或向他人发送消息。
- 更新以任务 ID 和外部对象 ID 定位，先读当前状态，仅写差异；超时后先回读确认，避免重复创建。
- 同步后回读核对，并记录结果。看板失败时保留本地账本、未同步项和错误，不重复修改业务状态。
- 外部看板有新内容但与账本不一致时，先记录差异；涉及范围、优先级和批准记录的冲突交人工决定。

## 最小演练
用一个人工批准的小任务验证：读任务→创建关联→更新一次状态→读取 PR 与 CI→关联验收证据→人工验收后关闭任务。
记录实际操作与缺失能力。只完成工具配置时，不宣称总控流程已验证。
