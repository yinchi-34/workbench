# coding 技能（v1）

管编程里需要判断力、又跨仓库反复出现的两件事：代码评审和写测试。一直生效的工程原则在基底层 AGENTS.md，这里只写步骤和输出格式。

## 什么时候读哪个文件

| 任务 | 读 |
|------|----|
| 审查一个分支、PR 或一段 diff | [references/review.md](references/review.md) |
| 给函数、模块或新功能写测试；修 bug 前写复现测试 | [references/tests.md](references/tests.md) |

同一个任务两者都涉及时（例如“实现并补测试后自审”），先按 tests.md 写测试，再按 review.md 自审。

## 通用约定

- 先确认范围：审查默认是当前分支相对 main 的改动；写测试默认只覆盖本次改动涉及的代码。
- 仓库根目录 AGENTS.md 里有评审重点或测试约定时，以仓库层为准。
- 结论要能验证：引用具体文件和行号，测试要实际跑过并贴出结果。
