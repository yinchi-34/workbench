# 复盘（v1）

## 启动参数

调用格式：`/retro <功能名或任务编号>`。本次参数：$ARGUMENTS

参数为空或显示为未替换的占位符时（例如在 Codex 中调用），以调用方消息中注明的功能名或任务编号为准；仍不明确时，先向调用方确认，再开始工作。

## 背景

各业务仓库的原始资料分散在各自的 spec、任务列表、docs/notes/、PR 与看板中。本技能将其汇总到 workbench 的 evals/records/，用于跨项目查看进度、避免重复踩坑，以及对比不同工具与技能版本的效果。汇总数据将用于对比，因此须以实际记录为准。

## 步骤

1. **定位 workbench 仓库**。本技能由 sync.py 以链接方式同步，执行 `readlink -f ~/.claude/skills/retro`（Codex 为 `~/.agents/skills/retro`），结果向上两级即为 workbench 根目录。sync.py 无法建立链接时会改为复制（例如 Windows 未开启相应权限），此时无法通过链接定位，须询问用户。
2. **收集资料**。在当前业务仓库中读取：本功能的 spec、docs/plans/ 中的任务列表、docs/notes/ 中的问题记录、相关 PR（`gh pr view`、`gh pr checks`）以及审查报告中的打回次数。
3. **更新进度汇总**（evals/records/progress.md）。按仓库与功能名查找对应行：存在则更新阶段、返工次数、问题数与日期；不存在则追加一行。
4. **追加基线数据**（evals/prompts/results/baseline.csv）。每个已合并的任务追加一行，列含义见 evals/README.md。token 数通过 `npx ccusage session` 查询；无法获取的字段留空，并在 notes 中说明原因。
5. **登记问题**（evals/records/issues.md）。对 docs/notes/ 中本功能的每条记录：
   - 判断所属层次（功能、语言、框架与中间件、依赖、资源开销、测试本身、运行环境）与范围（通用或项目特有）；
   - 在问题索引中追加一行，详细记录以链接指向业务仓库；
   - 通用问题拟定回写至常见问题清单对应文件的条目，列入交回内容，经用户确认后再写入。
6. **总结规则与技能的效果**。列出未生效的规则、被反复违反的约束，以及建议修改的技能或清单条目。
7. **提交 workbench 的改动**。在 workbench 中新建分支并提交，开 PR，不直接推送 main。

## 交回内容

首行为"需要确认"或"可以继续"，其后依次为：

- 已更新的记录（进度汇总的行、基线数据的行数、问题索引的行数）
- 拟回写常见问题清单的条目（目标文件与条目内容）
- 规则与技能的效果总结及修改建议
- 缺失的数据及原因
- workbench 的 PR 链接

## 规则

- 数据无法获取时留空并说明原因，不得估算补齐。估算值会使后续对比失去意义。
- 不直接修改角色技能与需求设计技能的正文，只提出修改建议。技能修改影响所有项目，须由用户决定。
- 回写常见问题清单须经用户确认。清单条目会被所有项目的审查环节使用。
- 详细问题记录保留在业务仓库，workbench 只保存索引与链接，不重复保存内容。

## 须在首行写"需要确认"的情形

- 存在拟回写常见问题清单的条目
- 提出了修改技能的建议
- 无法定位 workbench 仓库，或缺失的数据影响对比
