# 功能类型：数据增删改查

适用于新增或修改资源、数据表、对外接口的功能。

## spec 中须明确的内容

| 项目 | 须回答的问题 |
|------|--------------|
| 资源归属 | 资源属于谁；如何校验请求方有权访问（例如引用的消息是否属于同一会话） |
| 输入校验 | 每个字段的类型、长度、数量上限；哪些字段由后端计算，不采信前端传入的值 |
| 删除策略 | 软删除还是硬删除；关联数据如何处理（级联、置空、禁止删除） |
| 事务边界 | 哪些数据必须在同一事务中写入；出错时返回什么 |
| 幂等性 | 重复提交或重试是否会产生重复数据；是否需要幂等键 |
| 列表接口 | 分页方式、排序字段、是否需要一并返回关联数据（防止 N+1 查询） |
| 资源开销 | 每日新增记录数与单条大小、新增索引；填入 spec 的"资源开销估算"表 |
| 错误码 | 每种失败情形对应的状态码与错误信息 |

## 数据模型的取舍

每个字段注明理由。存在多种存储方式时，写明各自的代价与选择依据。示例：引用内容只存文本，还是同时存来源消息 ID 与起止位置——前者足以拼接 prompt，后者可支持跳回原文高亮，但位置可能因渲染方式而失准，因此以文本为准、位置仅用于定位。

## 必备验收测试

- 正常创建、读取、更新、删除各一条
- 访问他人资源返回 4xx
- 超出长度或数量上限返回 400
- 删除后关联数据按删除策略处理（例如级联删除生效）
- 重复提交的行为符合幂等设计
