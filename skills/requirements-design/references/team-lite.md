# 协作档位：轻量

适用于改动集中在单一领域或改动量小、接口不涉及多方依赖、单机即可满足规模的功能。仅设三个 agent 角色，需求与接口由开发者在主会话中直接确定。

## 角色

| 角色 | 担任者 | 职责 | 禁止事项 |
|------|--------|------|----------|
| 产品经理与负责人 | 开发者与主会话 | 编写 spec（含 API 与数据模型），审核任务列表，处理"需要确认"的报告 | — |
| 规划者 | 强模型 | 拆分任务，编写验收测试，标注所需的专项审查 | 不编写实现代码 |
| 执行者 | 执行模型 | 按任务实现，使测试通过 | 不修改测试，不超出任务范围 |
| 审查者 | 另一个 agent | 审查测试覆盖与代码质量 | 只提出问题，不修改代码 |

## 流程

1. 主会话按 requirements-design 技能编写完整的 spec，开发者确认。
2. 规划者拆分任务、编写验收测试，开发者审阅任务列表。
3. 每个任务依次交由执行者、审查者处理；审查打回最多两轮，仍未通过则交由开发者处理。
4. 任务确有需要时，可单独调用专项审查者，无须升级档位。

## 在 Claude Code 中的对应

使用 fullstack 模板时，在单一会话中直接调用本领域的 planner、executor、reviewer 子 agent（职责由 role-planner、role-executor、role-reviewer 技能定义）；不启用产品经理子 agent 与负责人会话，也无须建立 git worktree。

## 人工审核节点

与完整档位相同：spec 定稿、接口契约变更、对测试文件的任何修改、同一问题连续两次未能解决、最终验收。

## 升级为完整档位的信号

- 前后端因接口理解不一致而返工
- 同一功能需要前后端同时开发
- 审查中反复出现并发、缓存等专项问题
