# 功能类型：流式与长连接

适用于 SSE、WebSocket、模型流式输出及其他长时间运行的请求。

## spec 中须明确的内容

| 项目 | 须回答的问题 |
|------|--------------|
| 协议选择 | SSE、WebSocket 还是轮询；选择理由（单向推送通常 SSE 即可满足） |
| 连接建立方式 | 浏览器 EventSource 只支持 GET；如需 POST，前端须自行解析流 |
| 消息状态 | 状态集合与转换条件，例如 pending → streaming → done / error |
| 断开处理 | 客户端断开后，服务端是否停止生成、如何释放资源、已生成的内容是否保存 |
| 超时 | 首字节超时与总时长上限；超时后消息状态如何设置 |
| 重连与续传 | 是否支持断线重连；重连后从何处继续，还是重新生成 |
| 对规模的影响 | 每个用户同时持有的连接数；并发连接数估算是否需要更新 |

## 必备验收测试

- 正常完成：消息状态最终为 done，内容完整
- 客户端中途断开：服务端的处理协程退出，不残留 goroutine
- 上游出错或超时：消息状态为 error，不长期停留在 pending 或 streaming
- 同一消息重复订阅时的行为符合设计
